# «Байна Ядайк» v50 — кэшированный матовый объём карточек

Дата: 2026-10-24. База v49 `d2ffa2ae0f179c98b57d3700b7251db29371ef13`, сохранена резервная ветка `backup/bayna-v49-before-card-shadow-cache-20261024`.

## Основание для эксперимента

Пользователь предоставил показатели диагностического Android Release на Xiaomi при обновлении дисплея 120 Гц. На экране «Учебник» с обеими группами теней выключенными: GPU p95 ≈8,3 мс, 6/120 кадра >8,33 мс. С тенями карточек включенными и тенями рисунков выключенными: GPU p95 ≈11,2 мс, 35/152 кадра >8,33 мс; UI p95 3,8 мс. Измерения не являются строго контролируемой парной серией. **Они указывают на возможную цену отрисовки BoxShadow, но не доказывают 120 FPS.**

## Изменения с сохранением внешнего вида

- `scripts/generate_cached_card_shadows.py`: четыре компактные PNG-текстуры теней для исходных 2-слойных обычных и 3-слойных акцентных светлых карточек и тёмной темы. Радиусы, смещения, прозрачности и цвета взяты из исходных `BoxShadow` в `neumorphic_components.dart`; Gaussian sigma рассчитывается из blurRadius, затем маска уменьшается с 3x до 1x.
- `lib/ui/neumorphic_components.dart`: **только** если `--dart-define=BAYNA_CACHED_CARD_SHADOWS=true`, для радиусов 21/22 используется 9-срезная картинка позади неизменённой поверхности и границы. Сам `BoxShadow` для таких карточек не рисуется. Иначе исходный `BoxShadow` остаётся. Условие независимой диагностики карточек ВЫКЛ по-прежнему отключает оба способа.
- `scripts/generate_static_artwork_shadows.py` сохраняет `card__*.png` и не удаляет кэш при генерации силуэтных теней иллюстраций.
- `test/cached_card_shadow_test.dart` и `scripts/tests/test_cached_card_shadows.py` проверяют опциональность, исходную геометрию, фон, скругления, тему, переключение A/B, состав PNG и детерминированность. Старые тесты, учебные данные, PDF, аудио, настройки, навигация не изменены.
- Диагностический `com.example.arabic_academy.perf50` ARM64 Release APK подписывается **development** ключом и устанавливается отдельно от основной версии и v49. Его нельзя позиционировать как production-обновление.

## Особенности и риски

PNG-размытие предварительно рассчитывается через Pillow; оно может слегка отличаться от Flutter/Impeller Gaussian на реальном устройстве. 9-slice не следует включать в обычный релиз до пользовательского сравнения мягкости 3D в светлой/тёмной теме. Изображения должны оставаться без рамок, артефактов углов, полос между срезами. Для нестандартного радиуса предусмотрен оригинальный BoxShadow fallback. Визуальный тест на физическом Xiaomi **ещё требуется**.

## Проверка

Workflow: `.github/workflows/bayna-v50-cached-card-shadows.yml`:
- performance contract / assets / Android configuration, Flutter analyze;
- все прежние фокусные GPU и scroll тесты и отдельный тест cached mode;
- общие unit/widget тесты в четырёх шардах;
- ARM64 Flutter AOT/R8 со статическими силуэтными масками и кэшированными тенями карточек;
- проверка apk-signature/ABI/package name/пакетирования кэша.

**Статус измерений:** это кандидат на снижение raster p95, а не доказанное ускорение. На одном и том же экране «Учебник» сравнить v49 и v50 в режиме обеих теней ВКЛ по GPU p95/количеству кадров >8,33мс после двух прогревочных проходов; провести два повторения, зафиксировать условия и температуру, сделать скриншоты 3D. При регрессии плавности или дизайна оставить v49 и отказаться от кэша. Отдельно рассмотреть Android FrameTimeline/Perfetto для измерения фактически показанных кадров.

**Performance contract: preserved / intentionally modified with evidence.** Код поведения и состояния не изменялся. В v50 намеренно изменена только внутренняя отрисовка теней при opt-in диагностическом флаге, со встроенным fallback, резервной веткой и тестами. Подтверждение визуальной идентичности и GPU на физическом телефоне пока отсутствует.
