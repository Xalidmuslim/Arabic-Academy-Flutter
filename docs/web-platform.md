# «Байна Ядайк» — одна кодовая база для Android и Web

## Что добавлено

Ветка `codex/bayna-web-pwa-20261110` основана на
`codex/bayna-system-managed-refresh-20261110`. Исходный Android-код,
арабские статьи, русские значения, огласовки и идентификаторы не изменялись.

Единый `pubspec.yaml` и `assets/data/corpus_manifest.json` используются
как для сборки Android APK, так и Flutter Web. Обе сборки в
`.github/workflows/dictionary-web-preview.yml` создаются **из одного коммита**.

- Web: `flutter create --project-name bayna_dictionary --platforms web .`,
  `flutter build web --release --base-href /Arabic-Academy-Flutter/`.
- Android: `flutter create --project-name bayna_dictionary --platforms android,web --org com.xalidmuslim .`,
  `flutter build apk --release --target-platform android-arm64`.
- CI: `flutter analyze`, `flutter test`, контроль всех файлов корпуса в web-бандле,
  проверка ненулевого размера APK.
- Временные результаты: GitHub Actions artifacts
  `bayna-dictionary-web-preview` и `bayna-dictionary-android-preview`.

## Как получить общие обновления

Редактировать статьи и код следует в **общей исходной ветке** и после проверки
собирать оба релиза из одного SHA. Одновременное обновление на устройствах
не происходит само по себе: сайт требует деплоя, APK требует новой установки
или механизма доставки обновлений.

Локальные избранное, закладки, история поиска и настройки в Android и браузере
**не синхронизируются**: сейчас используется `shared_preferences` на каждом
устройстве отдельно. Для аккаунтов и синхронизации понадобится авторизация,
удалённое хранилище и политика защиты пользовательских данных.

## Деплой

Веб-сборка имеет `base-href` для GitHub Pages под
`/Arabic-Academy-Flutter/`. Публичный сайт **пока не включён**: нельзя
переключать Pages этого репозитория, пока не проверено, что там не опубликован
другой проект. После успешной CI-сборки можно развернуть артефакт на отдельном
домене / выделенном хостинге, либо включить Pages из GitHub Actions
после проверки текущих Pages-настроек.

## Проверка перед публикацией

1. Открыть release web-бандл в Chrome Android, Safari iOS и десктопном Chrome.
2. Проверить арабский шрифт и все огласовки, поиск без огласовок,
   направление текста RTL и длинные значения.
3. Проверить восстановление избранного/закладок при перезагрузке сайта.
4. Отдельно проверить арабскую озвучку в каждом браузере; TTS зависит от
   платформы и может требовать пользовательского действия.
5. Проверить стартовую загрузку и прокрутку большого словаря на реальном телефоне.
6. Проверить установку PWA и офлайн-запуск: наличие manifest само по себе
   **не гарантирует** офлайн-доступность или предложений установки.
7. Сравнить содержимое и внешний вид Android и Web, затем публиковать.
