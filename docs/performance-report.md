# Производительность: изменения и ограничения измерений

## Устранённые источники нагрузки

Шрифты теперь локальные, запуск бесплатного обучения не ждёт Supabase/Firebase, иллюстрации оптимизированы в WebP и декодируются под мобильный размер. Старые графические атласы/вырезки не включаются в новую Flutter asset-конфигурацию. Крупные PNG хранятся только как исходники дизайна. Новая тема обходится без дорогого blur, карточки используют два мягких слоя теней, длинные каталоги/списки строятся лениво. Короткие анимации учитывают системное отключение и пользовательскую настройку.

Состояние и хранение выделены из main в модули. Записи сериализуются, отправка событий идемпотентна, синхронизация авторизованного бесплатного обучения запускается после локальной загрузки и повторяется с минутным интервалом. Неудачная сеть сохраняет outbox, ограничивает запросы timeout и не выдаёт фиктивный успех.

## Что действительно измерено

В Linux установлен Android API 35 эмулятор, APK установлен и Activity запускалась. У среды отсутствует `/dev/kvm`; программная эмуляция вызвала ANR системных QuickStep/System UI/Phone до устойчивого тестирования интерфейса. Время такого запуска **не характеризует производительность приложения на телефоне**. Эмулятор остановлен, чтобы не ухудшать сборки. Утверждений о 60 FPS, расходе памяти, измеренном release/profile cold start на телефоне и отсутствии всех задержек не делается.

Визуальная проверка Flutter tester и обычные widget-тесты проверяют расположение/переполнение; они не заменяют Flutter Profile на Android/iPhone. Подробности и изображения: [visual-validation.md](visual-validation.md). Время/размеры сборок и фактические результаты команд приведены в [delivery-report.md](delivery-report.md).

## Воспроизводимый следующий замер

На физическом слабом Android и iPhone:

1. Соберите `flutter run --profile` с теми же локальными данными и production-подобной конфигурацией. Приложите модель устройства/ОС/commit, не смешивайте debug и release результаты.
2. Flutter DevTools Performance: cold/warm launch по 5 раз, главная → урок → практика → назад, список слов/курсов с длинным каталогом, крупный текст/RTL. Сохраните Timeline/FrameTiming и p50/p95 UI/raster времени, долю кадров выше display budget.
3. Memory: 20 повторов переходов, воспроизведение/запись, повтор загрузки; сравните heap/RSS и освобождение плееров/контроллеров после ухода.
4. Network throttling/offline: локальные уроки без сети, сохранение черновика, восстановление связи, повтор событий, ошибка внешних сервисов, истечение платного доступа.
5. Повторите с реальным старым профилем после обновления и обычным системным масштабированием.

Неразрешённые риски: часть верхнеуровневых слушателей перестраивает общий экран; бесконечная история локальных событий ещё не имеет archival/compaction политики; большие пользовательские JSON/каталоги требуют нагрузки на реальных данных; адаптивное видео/transcoding/CDN требуют внешней инфраструктуры. Это конкретные оставшиеся работы, а не доказательство завершённой оптимизации.

## Фактические размеры и время сборок

Финальный Release APK: 88,91с на три ABI, AAB: 45,79с, Debug: 29,38с в прогретой среде. ARM64 APK около 35,6 MiB, AAB около 66,4 MiB; точные байты/SHA в [android-artifacts.json](verification/android-artifacts.json). Это измерения сборок, не cold start/FPS. Артефакты подписаны development ключом и содержат проверенные новые ассеты.
