# Проверка безопасности

Это отчёт о проверенном коде и границах проверки, не сертификат безопасности развёрнутой системы.

## Реализованные ограничения

- Роли назначает сервер. Демо-переключатель действует только на локальные данные. Клиентские metadata, изменённый APK и запросы ученицы не создают учительские роли.
- Серверная RLS защищает публикацию, оплаченные курсы, назначение учительницы, группы и чужие персональные данные. Ответы тестов находятся в приватной схеме; серверная оценка не доверяет клиентским баллам.
- Покупки проверяются через серверные Google/Apple API, привязаны к аккаунту и конкретным продуктам. Неподтверждённая, чужая, просроченная или отозванная покупка не создаёт доступ. Webhook HMAC, допустимое время и идемпотентность проверяются сервером.
- Приватные файлы получают короткие signed URLs после проверки доступа. Срок URL ограничен лицензией. Полученную копию невозможно отозвать физически; ссылки сохраняют силу до истечения короткого TTL.
- Supabase-сессия сохраняется в FlutterSecureStorage; Android backup/device-transfer исключают файлы с токенами и ключами, сохраняя учебные SharedPreferences. iOS использует Keychain `first_unlock_this_device`.
- Личные учебные данные разделены по UUID аккаунта. Демо не публикуется автоматически. Каждое событие синхронизации проверяет владельца на клиенте и сервере; локальный результат не становится серверной оценкой.
- Черновики/заметки с конфликтом сохраняют обе версии для явного выбора. Архивирование урока не стирает историю. Обычное обновление не очищает прогресс.
- Запись требует разрешения микрофона; отправка/распознавание — отдельного согласия. STT не выдаётся за фонетическую оценку.
- Подтверждённое удаление аккаунта запускает серверный процесс очистки/анонимизации; ошибка внешнего удаления не маскируется успехом. После подтверждённого удаления очищается локальный namespace только этого аккаунта.
- Все privileged функции имеют закрытый PUBLIC execute и фиксированный search_path. Service-role, store, LiveKit и STT секреты отсутствуют в клиентской конфигурации.

## Независимая проверка и исправления

Отдельное чтение кода выявило гонку между выдачей upload ticket и удалением аккаунта, ошибку признания ещё действующей отменённой/льготной Google-подписки, несовпадение multiple-choice ответов, игнорирование категорий push, отсутствие backup исключений, неполный ответ dispatch, запрет data publishing для чата ученицы, отсутствовавший приглашательный RPC и отсутствие русского prompt в онлайн-задании. Исправления проверяются регрессионными SQL/Deno/Flutter тестами; upload/deletion дополнительно проверяется реальными параллельными соединениями PostgreSQL.

## Ограничения перед запуском

Не проведены внешний penetration test, аудит рабочих аккаунтов/ключей, реальная SMS-доставка, live-store/sandbox покупки, APNs/FCM доставка, Storage HTTP и LiveKit с реальными устройствами без предоставленных аккаунтов. Структурные backup-тесты не заменяют аппаратный backup/restore тест. Учебные локальные JSON сохраняются в sandbox приложения, но не шифруются как банковские данные; для требований к шифрованию на устройстве нужен отдельный threat model.

Нужны защита OTP от злоупотреблений, мониторинг квот, регламент персональных данных и удаления, регион хранения, сроки retention, восстановление из резервных копий, cleanup jobs, проверенный billing gateway и ротация секретов. Эти настройки принадлежат владельцу и не имитируются локальными тестами. Доступ к действующей комнате LiveKit отзывается также на стороне сервера комнаты; истечение JWT не отключает уже открытое соединение само по себе.

Команды воспроизведения: `bash scripts/test_backend.sh`, (включая `scripts/test_backend_races.py`), `bash scripts/test_backend_edge.sh`, `flutter test --no-pub`. Точные итоги текущего запуска: [delivery-report.md](delivery-report.md).
