# Native remote school panel

`RemoteSchoolScreen(backend: backend, embedded: false)` is the public router entry point. Set `embedded: true` inside a parent with bounded height to omit the extra Scaffold/AppBar. The optional `api` argument injects the repository for tests; production uses `RemoteSchoolApi(backend)`. The public file re-exports `RemoteSchoolApi`, `SchoolLessonDraft` and `SchoolExerciseDraft` for compatibility.

## Module boundaries

The public screen contains the access wrapper, section navigation and composition. `remote/school_api.dart` owns server role checks, paginated reads and RPC calls; `school_models.dart` owns draft validation and lossless wire serialization. Catalog, lesson, exercise, group, submission and report widgets live in their corresponding `remote/*_panel.dart` / `lesson_editor.dart` files. `school_widgets.dart` contains the shared themed Panel helpers, native forms, confirmation dialogs and error/access views. The existing local teacher editor remains independent.

## Access and configuration

Use the configured `BackendService` with `SUPABASE_URL` and `SUPABASE_ANON_KEY`. The panel requires an authenticated account whose role is read from `server_roles`. No local demo switch or user metadata authorizes it. Every repository read and mutation rechecks the role; every nested page retains an access guard. Failed role reads deny access. Account changes hide existing data and require reopening the panel. Server RLS and definer RPCs enforce the actual course/group/student boundaries; client filtering is an additional convenience, never a substitute.

Teacher catalogs are restricted to `course_teachers`; teacher group listings to their `teacher_id`. Administrators can see their RLS-permitted catalog/groups. Profile pickers request only IDs and display names, and membership addition verifies enrollment for the group's course. Reads are paginated in batches of 200 with a stable ordering. Counts in reports come from the resulting real rows, including manual-review attempts and revision-requested submissions.

No new dependency is required beyond the coordinator's installed integration packages. No Firebase initialization is performed by this panel, and unconfigured external services produce errors.

## Phone workflows and exact RPCs

- Browse course → level → book → unit → lesson; create each level with native forms. Call `create_course(p_title,p_access_tier,p_source_policy)`, `create_level(p_course_id,p_title,p_position)`, `create_book(p_level_id,p_title,p_position,p_edition,p_license_reference)`, `create_unit(p_book_id,p_title,p_position)`, and `create_lesson(p_unit_id,p_title,p_position)`. Ownership is assigned by the server. Publish a course through confirmed `publish_course(p_course_id)`.
- Edit Arabic/Russian lesson metadata, text/media blocks, dialogue lines, vocabulary and grammar/examples. Block steps include `introduction`. Optional linguistic fields from migration 010 are editable; supplied roots/forms/examples are preserved without generating linguistic facts. Existing lesson `source_locator` objects and unknown manifest keys survive saves. Metadata-only saves omit `p_content`; content edits send complete blocks/dialogues/vocabulary/grammar arrays with existing UUIDs. `save_lesson(p_lesson_id,p_expected_version,p_patch,p_content?)` protects conflicts. Dialogues have no server position field; their lines do. Vocabulary IDs preserve reviews/bookmarks.
- Preview the current unsaved draft, inspect/copy its complete JSON, and confirm publication, return-to-draft or archiving. Conflicts keep the draft on screen. Reloading a server version or exiting with unsaved changes requires confirmation. Preview displays attached media references; the upload route handles the actual bounded private upload. Attach only `media` rows with `upload_state=ready` scoped to the lesson; block bodies store `media_id`, never a public Storage path.
- Build single-choice, multiple-choice, text-answer and manual exercises. Generate stable exercise/question/option UUIDs using `AcademyState.newId`. Call `save_exercise(p_exercise_id,p_lesson_id,p_expected_version,p_definition,p_questions)`. Existing automatic exercises require explicit replacement of every closed answer and new answers for each question: the client never reads `private.answer_keys`. Single-choice answers are option UUID scalars; multiple-choice answers contain one complete ordered UUID array; text comparison is exact or explicitly `text_trim`, preserving Arabic diacritics. Manual questions send no automatic answer keys. Both lesson and exercise saves require a server-confirmed newer version.
- Create groups with `create_group(p_course_id,p_title)`. The current SQL deliberately permits `set_group_member(p_group_id,p_student_id,p_active)` only to administrators; teachers can view their groups but cannot self-assign students. Administrators select an enrolled profile or enter a validated account UUID and can confirm removal.
- Assign published exercises from the group's course with `create_assignment(p_group_id,p_exercise_id,p_title,p_due_at)`. View actual submissions, revision history, grades and feedback; call `grade_submission(p_submission_id,p_revision,p_score,p_feedback)` for the displayed revision, or `request_submission_revision(p_submission_id,p_revision,p_reason)`. Awaiting-revision or already-graded work cannot be graded again in this UI. Review manual attempts through `review_attempt(p_attempt_id,p_score)` within the server exercise's maximum score.
- Compose a notification for a scoped group member. Confirm `create_notification(p_student_id,p_group_id,p_kind,p_body,p_idempotency_key)`; retain the UUID/body across uncertain creation retries. Query `notification_dispatch_status(p_notification_id)` before enabling a separate user-triggered `dispatch-notification` Edge call. FCM acceptance counters are server responses, not device-delivery claims. Unknown/reserved/failed states require status checking/operator reconciliation instead of blind resend.

Unsupported outer content/question/option fields or exercise kinds close destructive replacement; known metadata can still be edited for a lesson. Nested JSON in block bodies, question prompts and grammar examples is retained. No optimistic success state, invented statistics, synthetic invitation or locally unlocked access is used.

## Activation and invitations

Deploy the documented migrations through 013 and Edge Functions from [backend.md](backend.md), configure Supabase Auth/SMS and create actual server teacher/admin assignments. Private upload and signed-media services require deployed functions/Storage policies. FCM dispatch additionally requires `FCM_SERVICE_ACCOUNT_JSON` on the server and registered device tokens; no service credential belongs in Flutter.

The backend review-fix contract now defines `create_group_invite(p_group_id uuid)` → `{code, expires_at}` and `claim_group_invite(p_code text)` → `{group_id, course_id, title}`. The teacher displays only validated server-issued 32-character hexadecimal codes with a valid expiry; the learner can join through the online-courses header. Codes are single-use and expire after 24 hours, and only active consenting students can claim them. Invitations do not grant a teacher role, purchase, course entitlement or paid enrollment. Missing deployments return an activation error, never a synthetic code. See the worker's current migration and deployment requirements in [backend.md](backend.md).

## Learner review fixes and school homework

`OnlineCoursesScreen(backend: backend)` and `OnlineLessonScreen(backend: backend, lessonId: id)` retain RLS-protected catalog access. Arabic prompts are separate from Russian `prompt.translation`, with `prompt.text` as the legacy fallback. Single-choice sends a scalar option UUID; multiple-choice sends selected option UUIDs ordered by the public options list. A learner never downloads answer keys or grants themselves completion. The server grades `submit_attempt`, and `complete_lesson` alone authorizes completion of the current lesson version. Uncertain attempts retain a frozen key/body on the current screen for retry.

Dialogue headers and ordered `dialogue_lines` are loaded through public RLS queries and rendered in the dialogue step. Attached media is matched to the same lesson's ready, RLS-visible media row before requesting `protected-media` through `BackendService.signedMediaUrl`. Images and native just_audio/video_player controls load only after an explicit open action; controllers are disposed when their widget closes or the account changes. URLs from arbitrary block JSON are ignored. No premium content is bundled or persisted as an offline course. PDF viewing is not implemented in this screen.

`OnlineHomeworkScreen(backend: backend, state: accountState)` lists assignments from the authenticated student's active group memberships. The optional state must have `academy_account_<userId>` namespace; when omitted, the screen opens that same account's persistent workspace. Pass the coordinator's current account state when embedding in the existing router. The editor shows actual due dates, submission status/revision, question instructions, grade feedback, requested changes and revision history. It sends bilingual text via `submit_assignment(p_assignment_id,p_expected_revision,p_idempotency_key,p_body)`. Student PDF/image attachments are intentionally unavailable: the current upload RPC permits student audio only, so local files are never represented as submitted attachments.

Before sending, the editor persists an immutable outbox with the key, expected revision and text body in `AcademyState.drafts['online_assignment:<assignmentId>']`. Draft storage rejects demo and mismatched account namespaces. Network uncertainty preserves that payload for restart/retry; history containing the same key/body can acknowledge a lost response without creating another revision. Conflicts preserve the text and require an explicit revision comparison before resetting the outbox. No local teacher grade or local homework submission is reused as a server result. Author-learning sync excludes `draft_saved` events whose `draft_id` starts with `online_assignment:`: server-assignment outboxes use `submit_assignment`/history rather than self-study event replay. This also prevents duplicated large text payloads from blocking the author-learning sync queue.

`notification_preferences.dart` exports `saveNotificationPreference(backend, categoryId, enabled, [fullPreferences]) → Future<Map<String,dynamic>>`. Stable IDs are `lesson`, `assignment`, `live`, `feedback`, `message`, `review`. It sends only `{preferences:{notification_categories:{<id>:enabled}}}` in `update_user_preferences.p_patch`, whose atomic recursive merge preserves other categories, unknown preferences, consent and the global notification switch. A stale full snapshot is accepted for source compatibility but never forwarded. The helper requires an authenticated unchanged account and an acknowledged own `user_settings` row.

Shared learner adapters and draft serialization are in the already-authorized `teacher/remote/online_learning_api.dart` and `homework_draft.dart`; native signed-media lifecycle is in `online_media_preview.dart`. This keeps the learner UI files free of direct PostgREST query orchestration and outbox serialization. These adapters require only learner authentication, not a teacher role.

## Verification

Scoped review-fix verification on 2026-10-12: analysis reported no issues and all 42 tests passed (15 learner / 27 teacher). Tests use injected server responses; device/network checks are separate.
Run from the repository with Flutter 3.35.7 / Dart 3.9:

```sh
source /workspace/academy-env.sh
flutter analyze --no-pub lib/features/teacher/remote_school_screen.dart lib/features/teacher/remote test/remote_school_screen_test.dart lib/features/learning/online_courses_screen.dart lib/features/learning/online_homework_screen.dart lib/features/learning/notification_preferences.dart test/online_learning_test.dart
flutter test --no-pub test/remote_school_screen_test.dart test/online_learning_test.dart
```

Tests exercise role denial/revocation, account changes, embedded navigation, real RPC argument shapes, full lossless payloads, private-answer replacement, finite score validation, optimistic conflicts, native dialogue creation, enrollment-scoped administrator membership, native UUID exercise creation, notification dispatch status, Arabic RTL/diacritics, and tappable hierarchy navigation on a 320px phone at 2× text scale. These tests use injected server responses; they do not claim remote deployment, SMS/FCM delivery or native device playback/network validation. Visual tests can use `OnlineCoursesScreen(backend: backend)` (join header), `OnlineLessonScreen(backend: backend, lessonId: id)`, and `OnlineHomeworkScreen(backend: backend, state: accountState)`; optional injected `OnlineLearningApi` values provide scoped test data.
