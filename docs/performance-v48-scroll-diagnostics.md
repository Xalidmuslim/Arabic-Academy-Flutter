# Байна Ядайк v48 — диагностика вертикальной прокрутки

Дата: 2026-10-24. База: `codex/bayna-v47-static-shadow-cache-20261023` (6b3bae7). Навыки Android и AGENTS.md подключены в v48. Для диагностики добавлен отдельный CI workflow, но код приложения, учебные материалы, работающие оптимизации, 3D-дизайн, PDF, настройки и сохранённые данные не изменены.

## Что подтверждено по исходникам

- `course_screen.dart` использует `CustomScrollView` и `SliverList.builder` для уроков/разделов; словарь урока тоже строится лениво. Нет основания заменять прокрутку «на другую» вслепую.
- `fitted_study_artwork.dart`: обычный путь по-прежнему использует `ImageFiltered.blur` для силуэтных теней. В v47 уже реализован альтернативный путь подготовленных PNG-масок при сборке с `BAYNA_STATIC_SHADOW_ASSETS=true`. В проверяемом APK маски **включены**.
- `neumorphic_components.dart`: несколько `BoxShadow` (до blurRadius 35) рисуются на матовых 3D-карточках. Это потенциальный дорогостоящий GPU/raster-участок, но причинность не установлена.
- `performance_probe.dart`: диагностический HUD уже показывает частоту дисплея Flutter, UI p95, raster/GPU p95, число кадров за бюджетами 8.33 и 16.67 мс; четыре режима A/B отключают тени карточек и силуэтов независимо. Частота дисплея **не является фактическим FPS**.

Ранее на других версиях были raster p95 порядка 12–17 мс в тяжёлых сценариях и 3.9 мс в более лёгком режиме со снятыми тенями. Эти показатели не являются контролируемым сравнением v47 → v48 и не доказывают достигнутый FPS.

## Автоматическая проверка в GitHub Actions

`.github/workflows/bayna-v48-scroll-diagnostics.yml` запускается при push в v48 и делает:
- проверку исходных ассетов, контрактов производительности и Android-конфигурации;
- генерацию статических масок, `flutter analyze` и фокусные Flutter UI/GPU/scroll тесты;
- полный набор Flutter тестов в 4 независимых шардах;
- диагностический ARM64 Release AOT/R8 APK с обоими `--dart-define` флагами, с проверкой подписи, ABI и упаковки масок;
- отдельный developer-signed пакет `com.example.arabic_academy.perf48` с названием «Байна Ядайк GPU 48». Production-приложение и его пользовательские данные не затрагиваются.

Не объявлять тесты зелёными и APK готовым до проверки завершённого workflow и самого APK.

## Протокол диагностики на Xiaomi

1. Открыть раздел со списком уроков, дать иллюстрациям прогрузиться; на одинаковом участке несколько раз быстро прокрутить вверх-вниз.
2. На диагностическом HUD записать `Экран Flutter, Гц`, `UI p95`, `GPU p95`, `>8,3мс N/120`, `>16,7мс` после не менее 120 кадров.
3. В том же разделе нажимать переключение четырёх режимов теней: обе ВКЛ, только тени рисунков ВКЛ, только тени карточек ВКЛ, обе ВЫКЛ. После каждого переключения статистика сбрасывается. Повторить одинаковую прокрутку *два раза* для каждого режима.
4. Повторить в «Разговорных ситуациях» и на главном экране; не смешивать данные разных маршрутов, жестов, тем и температур. Снять скриншоты каждого завершённого замера.
5. Если именно GPU p95 сильно падает при отключении только одной группы теней, оптимизировать подтверждённый участок, сохраняя матовый 3D-объём; если UI p95 высок — исследовать перерасчёты и layout.
6. Если GPU/UI p95 укладываются в 8.33 мс, но движение всё ещё выглядит как 60 FPS, отдельно профилировать Android FrameTimeline / Perfetto и Android refresh policy. HUD не измеряет фактически показанные кадры.

## Статус

Статический аудит: выполнен. Автоматические тесты и APK: запуск/результат требуют проверки Actions. Измерения на физическом Xiaomi: **не проводились в этой сессии**. Нельзя заявлять «120 FPS» до одинаковых тестов на реальном телефоне.
